# Remote-UI profile lane

`remote_ui.py` supports `--profile plain|lazy` and defaults to Plain Neovim. It uses an owned short-root server and an owned bidirectional PTY driver in the recorded `WorkspaceFixture` pane. The driver forwards fixture terminal input to the `nvim --remote-ui` child and records rendered terminal bytes; it is not the output-only checkpoint relay.

The command requires an exact clean `--revision`, a new artifact directory, and the private `--target-file` contract. It writes its context before creating a fixture, validates server/socket/PID/start and parent PTY identities, requires one attached UI with dirty synthetic content and the protocol-speaking fixture LSP, then records fixture native key receipts, calibrated capture, detach, and retained dirty/LSP state. The driver enters raw mode only for a TTY parent and restores its exact termios settings before exit.

The optional `--clipboard` lane is off by default. Only after the remote UI has attached and passed readiness, the native macOS lane compiles the exact archived `tests/native/clipboard.swift`, starts its bounded 60-second line-JSON helper on the general pasteboard, and uses native printable normal-mode input for `"+p` and `gg"+yy` in an owned empty scratch window. Other platforms record this lane as `UNVERIFIED`; a Swift compiler without macOS AppKit is not a supported native clipboard environment. RPC checks the pasted buffer and the yanked line plus newline. The helper is terminated and reaped in `finally`; a `FAIL` or `UNVERIFIED` restoration receipt is retained and is never converted into a successful result. It does not record the original clipboard contents.

The scratch window is closed and the original dirty buffer, window, and fixture LSP count are checked afterward. The register commands remain in normal mode, so no Escape key is sent; the receipt reports that fact as `UNEXERCISED`. Fixture focus is checked immediately before each native input. Source tests use an injected fake protocol/clipboard bridge without compiling or starting the AppKit helper and report that bridge as simulated; only a released native run can claim the platform bridge. The LazyVim profile archives only exact locally available pinned dependencies into its isolated site directory, records their provenance, imports `lazyvim.plugins`, and records unavailable optional integrations as UNVERIFIED. It never downloads dependencies. When those exact local sources are absent, the profile test verifies the preflight receipt and reports the source-flow lane as `UNVERIFIED` instead of claiming a run.

Clipboard comparisons run inside Neovim and return only boolean equality results. For a clipboard-enabled lane, the PTY driver's raw transcript stops before clipboard input and remains stopped through driver exit, so delayed foreign terminal bytes cannot be saved after scratch cleanup. Process identities and cleanup receipts continue to be recorded; structured key, comparison, restoration, and post-restoration capture receipts cover the remainder. The raw transcript does not cover that final interval.
