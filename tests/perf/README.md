# Comparable measurements

`tests/perf/compare --scenario shell-open --baseline <exact-sha> --candidate <exact-sha> --samples 30 --artifact-dir <new-directory>` extracts both exact commits and runs the **current** harness against both. The baseline does not need harness files. Pairs alternate AB, BA on the same host and isolated profile. Each side has 30 samples (100 is also accepted), separate labels even for equal SHAs, archive/tree identities, call bytes, evolving model state, output and an observed outcome. Exceptions and timeouts remain in the observations. Percentiles exclude failed observations and report the count and failures; the comparator does not report speedups against a failed baseline.

The `shell_dispatch_open_ms` metric measures the wall time of `herdr/pane.sh open`, including process supervision, against the fake API. It never starts a real editor. It is neither warm editor performance nor cold editor readiness. Overall PR00 perf remains UNVERIFIED even if every shell sample succeeds.

`--scenario controller-choice` dispatches the prototype bridge only when the coordinator releases its isolated live/performance slot. It preserves each runtime mode's separate outcome and metrics; planner/executor modes are experiments, not production controller speedups. Thirty actual interleaved lifecycle samples with warm show/hide, cold readiness, external calls, geometry, process count and RSS are still required for PR00. The separate native Cmd/visual evidence is also absent here.

For prototype integration, import `compare.py` and call `run_pairs(repo, baseline, candidate, samples, new_artifact_dir, measure=measure_lifecycle, real=True)`. The callable receives `(source_archive_path, owned_session, sample_artifact_dir)` and performs one actual lifecycle operation using the source it was given. It returns `{"status": "PASS"|"FAIL"|"UNVERIFIED", "metrics": {name: finite_nonnegative_number}, ...observations}`. The same callable is used for both archives, outside archive extraction/startup timing. Both arms create the same owned `XDG_CONFIG_HOME/herdr/config.toml` with supported update version and manifest checks disabled before any Herdr command; each session records the control's path, SHA-256, and applied flags in its evidence. An owned-session isolation failure persists its failing arm and then stops the comparison before another arm starts. Use `owned_session.run` for Herdr APIs and `owned_session.execute` for subprocesses. The API retains evidence and teardown failures; it does not turn arbitrary returned labels into a full PR00 verdict. Required metric names are listed in `compare.REQUIRED`.
