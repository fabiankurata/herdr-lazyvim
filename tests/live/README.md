# PR00 harness

`tests/live/run --scenario boot-isolation --real --revision <exact-40-char-sha> --artifact-dir artifacts/PR00/<sha>/lane-2` boots, snapshots, and tears down one owned Herdr server. The default source mode requires a clean checkout at that SHA. `--source-mode archive` extracts the exact commit from the local repository and records its tree and archive hash, even when the checkout contains other work. `--source-repo` selects the source repository; instrumentation always comes from this harness and its revision/dirty state is recorded separately.

Artifact directories must be new. A repeated path fails without replacing anything. `OwnedSession(existing_artifact_dir)` instead creates a unique evidence child, for prototype callers that already created their output directory. Historical evidence is never removed by either entry point.

`--scenario isolation` exercises synthetic repositories and raw PTY byte/resize capture. With `--real`, `live-pane` dispatches the existing direct 100-cycle owned-workspace transfer probe with interruption, sole-pane, and nudge scenarios; `remote-ui` dispatches its 100-cycle isolated PTY UI probe; `server-identity` dispatches the two-server namespace and delayed-effect probe; and `editor-profiles` delegates to the existing plain/LazyVim profile runner. Each writes its narrow result below `workload/`; the top-level receipt preserves exact source provenance. Archive provenance is recorded but is not claimed as an exercised live-pane runtime. A scenario name cannot provide evidence or bypass routing validation. Caller-supplied session/socket values are rejected before workload setup. Native Cmd shortcuts, screenshots, clipboard, GUI focus, and full PR00 lane acceptance remain unverified.

## Runtime API

The prototype API remains `OwnedSession(artifact_dir)`, `.env`, `.root`, `.socket`, `.session`, `.herdr`, `.proc`, `.run(*args, check=True)`, and the context manager. Optional keyword arguments support synthetic mode (`real=False`), target validation, bounded deadlines, and the performance-only `disable_update_checks=True` control. That control creates `$XDG_CONFIG_HOME/herdr/config.toml` under the generated runtime with supported `version_check = false` and `manifest_check = false` values before any Herdr command, mode 0600, and records its path, hash, and applied flags in the owned-session evidence. The runtime must be entered on the main thread so SIGTERM and KeyboardInterrupt unwind the context, including a failed `__enter__`.

`execute(argv, env=None, check=True, timeout=None)` supervises additional fixture processes. It runs in the owned root, checks isolated routing/configuration variables, tracks direct children, process groups and observed descendants, and closes the context on timeout/cancellation. Use it for bounded subprocesses. Long-lived external PTY clients created directly by a prototype remain that prototype's responsibility; importing this class does not automatically own arbitrary caller processes. Workloads must retain a foreground owner and must not double-fork into an unobservable daemon. Herdr's foreground server is the supported boot mode.

There is one boot/teardown implementation. It allocates `/tmp/hf-*` with `mkdtemp`, uses a random named session, sets HOME and all HOME/DIRS/RUNTIME XDG variables, and checks the empty named-session status before boot. API calls revalidate the target and cannot override it with command options or environment. Timeouts invalidate the context because a timed-out server mutation may still finish.

Teardown observes descendants before stopping their parents, signals only tracked process/start identities and owned child groups, reaps direct children, and requires all observed descendants to disappear before removing the runtime root. An observation, remaining-process, or removal failure retains the root and produces FAIL. Preexisting paths or an unexpectedly exiting foreground server also retain the root: unknown server state is never adopted or erased. Signal-delivery races are recorded separately; success still requires observed process disappearance and reaping. SIGKILL of the harness itself and machine failure cannot run Python cleanup and are not certified by these tests.

Evidence includes the runtime manifest, versions, process/start identities, API timing events, initial API snapshot, server output, and teardown result. Default identity evidence uses read-only socket metadata and socket-owner process identities plus their existing Herdr/Neovim descendants. It reads no argv, process environment, editor contents, or user source files. An unrelated named prototype session is not the default server.

## Local checks

`make test` uses the same supervisor with isolated HOME/XDG state and `HERDR_TEST_STATE_ROOT`, runs existing plugin/Neovim checks, and runs harness/perf unit tests. `HERDR_TEST_ARTIFACT_DIR` can select a new evidence directory. Tests use a synthetic executable and real disposable OS processes to inject preexisting sessions, boot/API/mutation timeouts, signal cancellation, target changes, and cleanup failures. The evolving fake pane API preserves process identity and input bytes through moves, focus, zoom, resize and injected mutation failures. It rejects unknown commands.
